<objective>
## Goal
Validate the four foundational assumptions of Phase 42.5 v2 BEFORE committing engineering time to provisioning, runtime, or verifier work. Each validation either confirms the architecture or surfaces a blocker that forces a plan revision.

## Purpose
Phase 42.5 v2 is a 6-plan, 14-gate engineering effort that gates Perseus launch (quality > launch date, locked 2026-04-07). Three of its substeps are unverified assumptions that, if wrong, invalidate the entire downstream plan. This research plan de-risks them up front so we don't burn weeks discovering a foundational blocker mid-build. Plus the legal memo gates all customer-facing daemon routing — must land before any code touches Titan, Clawdbot, or Deerflow operator-facing paths. Perseus does not launch until Phase 42.5 is fully cutover; this plan is the first concrete step toward that launch.

## Output
1. `docs/compliance/local-tier-licenses.md` — license memo covering Qwen3, Qwen3-VL, Qwen3-Embedding/Reranker, Parakeet (FluidAudio), Kokoro, Draw Things, and ReDrafter, with per-daemon allowlist
2. `shared/llm_client.py` — modified to propagate `perseus_chain_depth`, `task_class`, `daemon_name`, `architect_call` metadata through to LiteLLM via OpenAI `extra_body`
3. `tests/integration/test_metadata_propagation.py` — proves metadata round-trips end-to-end from any daemon through LiteLLM proxy and back into Langfuse traces
4. `docs/spikes/gbnf-mlx-vlm-spike.md` — proof-of-life report: does outlines GBNF actually produce schema-conformant tool calls through `mlx_lm.server` for Qwen3-30B-A3B in production conditions? Pass/fail with evidence

    Modify `shared/llm_client.py` to accept and propagate four new fields to LiteLLM via OpenAI `extra_body`:
    - `perseus_chain_depth: int` — how many sequential LLM calls deep this is in the current daemon task
    - `task_class: str` — short identifier for the task category (e.g. "ruflo.fix_classification", "titan.lead_extract", "hermes.alert_summary")
    - `daemon_name: str` — which daemon is calling ("perseus", "titan", "hermes", "clawdbot", "conway", "deerflow", "ruflo", "openjarvis")
    - `architect_call: bool` — for Aider pattern, whether this call is the architect (Opus) or editor (local Coder)

    The function signature:
    `def llm_call(messages, *, model, daemon_name, task_class, chain_depth=0, architect_call=False, **kwargs)`

    Implementation:
    - Inject the four fields into `extra_body` automatically — daemon code passes them as kwargs
    - The `chain_depth` parameter has a sane default (0) so existing call sites don't break
    - Add a context manager `with llm_chain(daemon, task) as ctx: ctx.call(...)` that auto-increments chain_depth across nested calls
    - Emit the four fields as Langfuse span attributes via the existing Langfuse callback (if Langfuse is wired) — verify by reading the Langfuse Python SDK docs for span attribute injection
    - Backwards compatible: any daemon that hasn't been updated still works, just with default metadata

    Write `tests/integration/test_metadata_propagation.py` with one test per daemon (8 tests) that:
    - Calls `llm_call` with mocked LiteLLM client
    - Asserts `extra_body` contains all four fields with correct values
    - Asserts the Langfuse callback receives the fields as span attributes (use a mock Langfuse client)

    Do NOT modify any daemon code yet — that's Plan 42-5-03's scope. This plan only changes `shared/llm_client.py` and adds the integration test.

    Avoid: hard-coding daemon name lists in `shared/llm_client.py` (use a typed enum or simple string validation); breaking the existing kwargs interface; modifying daemon files directly.
